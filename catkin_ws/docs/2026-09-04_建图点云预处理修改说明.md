# 建图点云预处理修改说明

日期：2026-09-04

## 修改目的

建图期间的 FAST-LIO 注册点云可能包含孤立噪点以及人员、车辆等移动物体的历史轨迹。本次参考 `AADCL/ugv` 中 Scout Mini 的点云映射方法，在机器人端为最终 PCD 地图增加离群点检测和三维贝叶斯运动滤波。

## 数据流

```text
/cloud_registered + /Odometry
        |
        v
有限值/距离裁剪 -> 0.05 m体素降采样 -> 半径离群检测
        |
        v
0.20 m三维贝叶斯占据 + 自由空间射线清除
        |
        +-> /ground_air/mapping/static_cloud（诊断）
        `-> cloud_map.pcd（地图保存）

/cloud_registered_body -> move_base局部代价地图（保持原链路）
```

运动滤波在线执行，但只改变地图记录器最终保存的 `cloud_map.pcd`。实时导航仍使用当前注册点云，因此正在移动的人或车辆仍会作为实时障碍参与避障。

## 重定位与局部避障职责（本次明确）

重定位加载的参考文件固定为保存包中的 `cloud_map.pcd`。该文件是本包经过静态确认和运动物体清除后的地图，不是当前传感器的实时点云；重定位器会先从 `/ground_air/active_map_pcd` 读取它，再用实时 `/cloud_registered` 作为观测进行匹配。因此“进入已处理地图”指的是参考地图已经处理完成，实时观测仍保持原始感知能力。

重定位成功后，自动导航的全局代价地图使用 `/map`，局部代价地图继续订阅 `/cloud_registered_body`。局部规划每次根据实时点云更新障碍物，动态人员和车辆不会因为保存地图的静态滤波而被忽略，也不会把 `/ground_air/mapping/static_cloud` 误用作避障输入。

```text
cloud_map.pcd（已处理静态地图） ──> 全局重定位参考
/cloud_registered（实时注册点云） ──> 重定位观测
/map（二维地图） ────────────────> 全局规划
/cloud_registered_body（实时点云） ─> 局部代价地图/避障
```

## 默认参数

| 参数 | 默认值 | 含义 |
|---|---:|---|
| `scan_voxel_size` | 0.05 m | 单帧降采样分辨率 |
| `radius` | 0.15 m | 离群点邻域半径 |
| `min_neighbors` | 2 | 半径内最少邻点数 |
| `temporal_voxel_size` | 0.20 m | 贝叶斯粗体素大小 |
| `min_hit_scans` | 8 | 静态确认所需最少帧数 |
| `min_observation_span` | 2.0 s | 静态确认最短持续时间 |
| `ray_stride` | 4 | 自由空间射线抽样步长 |
| `max_clearing_range` | 20 m | 最大射线清除距离 |
| `max_odom_age` | 0.20 s | 点云与里程计最大时间差 |

自体滤波默认关闭，等待实测雷达与机体边界后再启用。

## 接口变化

以下原有服务和话题保持不变：

- `/ground_air/mapping/start`
- `/ground_air/mapping/save`
- `/ground_air/mapping/cancel`
- `/ground_air/mapping/status`

新增只读诊断话题：

- `/ground_air/mapping/static_cloud`：当前已确认的静态地图点云，默认每 2 秒刷新。
- `/ground_air/mapping/dynamic_points`：当前未确认静态的点，默认不发布，可通过参数开启。

## 不受影响的功能

- FAST-LIO 输入、输出和 TF 不改变。
- 重定位仍使用原有实时注册点云。
- 导航代价地图仍读取 `/cloud_registered_body`，不会过滤掉当前动态障碍。
- `/map`、`map.pgm` 和 `map.yaml` 仍由现有 `dynamic_mapping` 链生成。
- 本次运动滤波只保证 `cloud_map.pcd` 的静态化，不承诺从 PGM 中删除所有瞬时动态物体。

## 安全和故障处理

- 仅在建图状态为 `RECORDING` 时处理和累计点云。
- 新建或取消建图时会清空候选体素、静态体素和清除历史。
- 点云与里程计坐标系不一致、时间差过大或姿态非法时丢弃该帧。
- 体素达到容量上限时停止记录并报告错误，避免内存无界增长。
- 地图点数不足时，原有保存服务继续拒绝生成空地图。

## 实机验收

1. 启动基础系统和建图系统，调用建图开始服务。
2. 让墙面等静态结构持续处于雷达视野中，约 2 秒后检查 `/ground_air/mapping/static_cloud`。
3. 让人员横穿雷达视野，并在离开后继续扫描原位置。
4. 保存地图，检查 `cloud_map.pcd` 不应出现连续的人体运动轨迹。
5. 使用新地图执行重定位，确认成功率和误差没有明显退化。

本次代码验证不启动底盘、不解锁飞控，也不发送任何运动指令。
