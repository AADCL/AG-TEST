## 1. 能做什么

| 功能 | 当前状态 |
|---|---|
| 遥控器手动驾驶建图并保存地图 | **已实机验证** |
| 重启后加载历史地图并进行未知位姿重定位 | **已实机验证** |

| 自动起飞、降落和飞行自主导航 | **当前禁用或不属于地面模态** |

## 2. 安全红线

- 现场必须有能立即操作遥控器的人，周围不得有人靠近车轮和桨叶。
- ROS 不负责解锁；只用遥控器按现有安全规程解锁。
- 建图时不启动导航、控制和任务执行器。
- `/ground_air/localization/valid` 不是 `True` 时禁止自主移动。
- 下发目标前必须用 `/move_base/make_plan` 做 `tolerance: 0.0` 的精确检查。
- 第一次目标只设 0.5～1.0 m，不直接进行 6 m 长距离测试。
- 当前规划 footprint 为 `0.6 × 0.6 m`；在未确认真实最大外廓前，必须额外扩大与墙体、桌腿和人员的距离。
- 出现高速旋转、方向相反、障碍判断异常或人员进入区域时，立即遥控器接管并急停。
- 障碍附近出现连续左右摆动、走走停停或路径贴障时，立即终止，不得提高速度继续。
- 软件急停不能替代遥控器和物理断电。
- 本手册不允许进行飞行、自动起降或空中模态切换。

## 4. 开机检查

建议顺序：

1. 确认地面构型、轮子、桨叶、电池和线缆安全。
2. 打开 H16 PRO 遥控器并检查电量。
3. 给机器人上电，等待机载计算机、CUAV Nora、Livox 和天空端启动。
4. 连接 GroundControlStation，确认能看到飞控连接和电量。
5. SSH 登录机载计算机并加载工作空间。
6. 检查 MAVROS：

```bash
rostopic echo -n1 /mavros/state
rostopic echo -n1 /mavros/extended_state
```

7. 需要检查遥控器时：

```bash
rostopic echo /mavros/rc/in
```

当前 H16 的 CH5/CH6 已确认约为：低 `1050`、中 `1500`、高 `1950`。必须以 `/mavros/rc/in` 的变化为准，不能只看遥控器屏幕。

## 5. 手控建图全流程

### 5.1 启动建图

终端一：

```bash
cd ~/catkin_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash
roslaunch car_bringup manual_mapping.launch
```

该入口启动 MAVROS、Livox、FAST-LIO、动态二维地图、地图记录器和 FAST-LIO→MAVROS 里程计适配；不会启动软件导航和地面执行器。

### 5.2 检查输入

终端二：

```bash
cd ~/catkin_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash

rostopic echo -n1 /cloud_registered/header
rostopic echo -n1 /Odometry/header
rostopic hz /cloud_registered
rostopic hz /Odometry
```

两个 header 的 `frame_id` 都应为 `camera_init`。

如需 PX4 Position 模式，再检查：

```bash
rostopic hz /mavros/odometry/out
rostopic echo -n1 /mavros/odometry/out/header
rostopic echo -n1 /mavros/state
```

`/mavros/odometry/out` 应持续更新。MAVROS 负责 ENU/FLU 到 NED/FRD 的转换，不需要操作者再做坐标转换。

### 5.3 开始记录

为本次地图选择一个从未使用过的 `map_id`：

```bash
rosservice call /ground_air/mapping/start "map_id: 'site_20260827_01'"
```

成功标志：

```text
success: True
state: 1
message: "recording registered point cloud and occupancy map"
```

`state: 1` 表示地图已经开始建立；刚开始 `point_count: 0` 属于正常现象。

### 5.4 观察状态

```bash
rostopic echo /ground_air/mapping/status
rostopic hz /map
```

| state | 含义 |
|---:|---|
| 0 | 空闲 |
| 1 | 正在记录 |
| 2 | 正在保存 |
| 3 | 保存完成 |
| 4 | 错误 |

### 5.5 遥控器驾驶

- 切到地面构型，低速、平稳驾驶。
- 沿边界走一圈，再覆盖内部通道。
- 从不同方向观察墙角、门口、立柱和走廊。
- 相邻路线保留重叠，避免急转、急停和原地高速旋转。
- 尽量形成闭环并回到起点附近。
- 建图期间不要停止 Livox、FAST-LIO 或建图 launch。

### 5.6 保存地图

停车并保持静止：

```bash
rosservice call /ground_air/mapping/save "{}"
```

成功返回中应有：

```text
success: True
map_directory: "/home/bitcq/catkin_ws/maps/<map_id>"
point_count: <大于0>
```

检查四个地图文件：

```bash
ls -lh /home/bitcq/catkin_ws/maps/<map_id>/
```

必须包含：

```text
cloud_map.pcd
map.pgm
map.yaml
metadata.json
```

确认保存成功后，再在终端一按一次 `Ctrl+C`，等待 launch 正常退出。不要 `kill -9`，也不要在保存过程中直接断电。

### 5.7 取消未保存地图

仅当确认不要本次缓存时：

```bash
rosservice call /ground_air/mapping/cancel "{}"
```

它不会删除已经保存的历史地图。

### 5.8 复制到 Windows 查看

在 Windows PowerShell 执行：

```powershell
$mapId = "site_20260827_01"
$dst = "$env:USERPROFILE\Desktop\$mapId"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
scp "bitcq@192.168.50.102:/home/bitcq/catkin_ws/maps/$mapId/*" "$dst\"
```

- `map.pgm`：普通二维图片或图像工具查看。
- `cloud_map.pcd`：CloudCompare、Open3D 或 PCL 工具查看。
- 无图形界面不影响车端建图和保存。

## 6. 未知初始位姿重定位

### 6.1 准备

1. 先停止 `manual_mapping.launch`。
2. 确认没有第二套 Livox、FAST-LIO 或定位 launch。
3. 把机器人放在历史地图覆盖区域，优先选择墙角、立柱等结构明显位置。
4. 保持雷达无遮挡，重定位期间机器人静止。

### 6.2 启动自主基础栈

终端一：

```bash
cd ~/catkin_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash

roslaunch car_bringup autonomy.launch \
  start_mavros:=true \
  start_navigation:=false \
  start_control:=false \
  start_mission:=false \
  start_video:=false
```

此时不产生地面运动指令。

### 6.3 检查输入

```bash
rostopic echo -n1 /cloud_registered/header
rostopic echo -n1 /Odometry/header
timeout 8 rostopic hz /cloud_registered
timeout 8 rostopic hz /Odometry
```

两者必须持续更新，frame 为 `camera_init`。

### 6.4 加载地图

```bash
rosservice call /ground_air/load_map "map_id: 'site_20260826_01'
source_uri: ''"
```

成功标志：

```text
success: True
message: "map activated; relocalization required"
```

检查 `/map`：

```bash
rostopic echo -n1 /map/header
```

预期 `frame_id: "world"`。

### 6.5 执行全局重定位

```bash
rosservice call /ground_air/relocalize "use_initial_guess: false
initial_guess: {}
timeout: 60.0"
```

该算法会在历史点云中自动寻找位置和朝向，因此不需要操作者输入初始位姿。机器人保持静止，最长等待 60 秒。

### 6.6 判断成功

```bash
rostopic echo -n1 /ground_air/localization/valid
rostopic echo -n1 /ground_air/localization/fitness
rostopic echo -n1 /ground_air/localization/rmse
rostopic echo -n1 /ground_air/localization/pose
rosrun tf tf_echo world camera_init
```

必须同时满足：

```text
valid = True
fitness >= 0.55
rmse <= 0.30 m
pose.header.frame_id = world
world -> camera_init 持续可查询
```

系统完整主 TF 链应为：

```text
world → camera_init → body → base_link → livox_frame
```

已验证结果约为 `fitness=1.0`、`rmse=0.041 m`。单次结果不代表全部场景均已验收，建议同点重启重复 3 次，再在相隔 2～5 m 且改变朝向的位置测试。

## 7. 地面单点自主导航与避障

本章只能在第 6 章成功后执行。

### 7.1 启动规划器

当前地面导航由 `GlobalPlanner` 生成全局路径，由 `TebLocalPlannerROS` 生成局部轨迹并结合实时 costmap 避障。

终端二：

```bash
cd ~/catkin_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash

roslaunch teb_local_planner_tutorials bz_navigation.launch \
  enable_drone_mode:=false
```

检查保守参数：

```bash
rosparam get /move_base/recovery_behavior_enabled
rosparam get /move_base/clearing_rotation_allowed
rosparam get /move_base/TebLocalPlannerROS/max_vel_x
rosparam get /move_base/TebLocalPlannerROS/max_vel_theta
```

必须为：

```text
false
false
0.1
0.2
```

检查避障输入：

```bash
timeout 8 rostopic hz /cloud_registered_body
rostopic echo -n1 /move_base/local_costmap/costmap/header
rosparam get /move_base/global_costmap/footprint
rosparam get /move_base/local_costmap/footprint
rosparam get /move_base/TebLocalPlannerROS/footprint_model/vertices
```

三处足迹必须一致，四个顶点均为 `x/y=±0.30 m`，对应 `0.6 × 0.6 m`。如果仍显示 `0.55/0.45`，说明当前 `move_base` 没有重启，不能继续测试。

### 7.2 启动控制并确认急停

终端三：

```bash
cd ~/catkin_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash
roslaunch ground_air_control control.launch
```

启动时软件急停必须为 `True`：

```bash
rostopic echo -n1 /ground_air/vehicle_status
rostopic echo -n1 /mavros/actuator_control
```

确认执行器输出为零。随后由操作者使用遥控器切到地面构型、`POSCTL` 并解锁。检查：

```bash
rostopic echo -n1 /mavros/state
rostopic echo -n1 /mavros/extended_state
```

期望：`connected=True`、`armed=True`、`mode="POSCTL"`；当前地面构型通常表现为 `vtol_state=4`。

### 7.3 检查目标是否可达

先查看当前位置：

```bash
rostopic echo -n1 /ground_air/localization/pose
```

用真实当前位置和目标填写命令：

```bash
rosservice call /move_base/make_plan "
start:
  header: {frame_id: 'world'}
  pose:
    position: {x: <当前X>, y: <当前Y>, z: 0.0}
    orientation: {x: 0.0, y: 0.0, z: <当前QZ>, w: <当前QW>}
goal:
  header: {frame_id: 'world'}
  pose:
    position: {x: <目标X>, y: <目标Y>, z: 0.0}
    orientation: {x: 0.0, y: 0.0, z: <目标QZ>, w: <目标QW>}
tolerance: 0.0"
```

只有 `plan.poses` 非空才继续。目标在未知区、墙体、地图边界或膨胀区时保持急停，重新选点。

### 7.4 下发目标

保持软件急停为 `True`，先发布目标：

```bash
rostopic pub -1 /move_base_simple/goal geometry_msgs/PoseStamped "
header:
  frame_id: 'world'
pose:
  position: {x: <目标X>, y: <目标Y>, z: 0.0}
  orientation: {x: 0.0, y: 0.0, z: <目标QZ>, w: <目标QW>}"
```

确认目标已被接受：

```bash
rostopic echo -n1 /move_base/status
```

然后才解除软件急停：

```bash
rosservice call /ground_air/emergency_stop "active: false"
```

成功响应必须包含：

```text
success: True
message: "operator reset; ground OFFBOARD confirmed"
```

失败时不要连续调用，立即保持/恢复急停并检查 PX4 状态。

### 7.5 运行监控

```bash
rostopic echo /ground_air/localization/valid
rostopic echo /ground_air/vehicle_status
rostopic echo /move_base/status
rostopic echo /navigation/cmd_vel
```

常用状态：`1=执行中`、`3=到达`、`4=失败`。定位失效、车辆方向错误、飞控退出 OFFBOARD 或出现异常旋转时立即停止。

障碍附近轻微修正不等于允许持续振荡。连续左右转向、速度反复归零或路径越来越贴近障碍时，按第 8 章立即急停并保存以下信息：`/move_base/status`、全局路径、局部轨迹和 local costmap。

### 7.6 到点与正常停止

到达后：

```bash
rosservice call /ground_air/emergency_stop "active: true"
```

确认：

- `emergency_stop=True`
- `flight_mode="POSCTL"`
- `/mavros/actuator_control` 全零

然后取消残余目标：

```bash
rostopic pub -1 /move_base/cancel actionlib_msgs/GoalID "{}"
```

## 8. 紧急停止

### 8.1 车辆异常运动

优先使用遥控器安全开关，然后执行：

```bash
rosservice call /ground_air/emergency_stop "active: true"
rostopic pub -1 /move_base/cancel actionlib_msgs/GoalID "{}"
```

不要等待日志，不要继续观察车辆是否会自己恢复。

### 8.2 正常取消任务

```bash
rostopic pub -1 /move_base/cancel actionlib_msgs/GoalID "{}"
rosservice call /ground_air/emergency_stop "active: true"
```

无论哪种停止方式，都要清除旧目标，避免以后解除急停时旧目标继续执行。

## 9. 有序多点任务的当前边界

`ground_air_mission` 已经有提交、启动、暂停、恢复、取消和状态接口，设计为按顺序到达任务点，并在每个地面任务点停留 2 秒。但 2026-08-28 的实机测试没有通过：一次任务与障碍发生碰撞；“前进 5 m，再返回起点并反向”的第二点出现 mission `state=5`、move_base `status=4 (ABORTED)`。

因此：

- 日常实机操作仍使用已验证的单点流程；
- 多点任务当前属于失败项，不得作为可用功能交付或无人看守运行；
- 不在人员和障碍复杂区域直接试跑多点任务；
- 后续测试必须逐点核对地图坐标、零容差路径和急停能力；
- 每个任务点都要分别执行 `make_plan tolerance=0.0`，并检查终点朝向和足迹膨胀区；
- 本手册不提供飞行任务点和起降操作。

## 10. 正常停机顺序

1. 取消当前导航目标。
2. 激活软件急停并确认执行器全零、PX4 为 POSCTL。
3. 在控制终端按 `Ctrl+C`。
4. 在导航终端按 `Ctrl+C`。
5. 在自主/定位终端按 `Ctrl+C`。
6. 确认没有地图保存过程正在进行。
7. 使用遥控器上锁，再按设备规程断电。

## 11. 快速排错

| 现象 | 首先执行 | 处理原则 |
|---|---|---|
| 找不到 `ground_air_msgs` 服务类型 | `source ~/catkin_ws/devel/setup.bash` | 每个新终端都要 source |
| 无注册点云 | `rostopic hz /cloud_registered` | 查 Livox、IMU、FAST-LIO |
| 仍显示 `_1`/`_loc` 旧话题 | `rosnode info /fast_lio_node` | 结束旧 launch 并重启，禁止启动第二套 FAST-LIO |
| 不能切 POSITION | `rostopic hz /mavros/odometry/out` | 查外部里程计和 MAVROS 状态 |
| 地图开始后点数为 0 | 等待并看 mapping status | 初始可为 0，持续为 0 才排错 |
| 地图加载失败 | 检查四个地图文件 | 不修复前不重定位 |
| 重定位失败 | 查 frame、点云、场景重叠 | 换结构明显位置，保持静止 |
| `valid` 变 False | 查点云是否超过 2 s 无更新 | 停止导航并重新定位 |
| 无全局路径 | `make_plan` 零容差检查 | 目标换到已知自由区 |
| 高速原地转圈 | 遥控器接管并急停 | 取消目标，确认恢复参数关闭，重启 move_base |
| 障碍附近左右摆动 | 急停并保存 local plan/costmap | 暂不提高速度或关闭障碍层，等待 TEB 调参复测 |
| 多点任务 `state=5`、move_base `status=4` | 急停、取消 Action | 该任务失败；分别检查每个目标的精确路径、朝向和局部可行性 |
| 解除急停失败 | 查 `/mavros/state` | 不重复盲调，保持停止 |

## 12. 一页式流程

```text
开机和 GroundControlStation 检查
        │
        ├── 建新地图
        │     manual_mapping.launch
        │     → 检查点云/里程计
        │     → mapping/start
        │     → 遥控器低速驾驶
        │     → mapping/save
        │     → 检查四文件
        │
        └── 使用历史地图自主导航
              autonomy.launch（不启动运动）
              → load_map
              → relocalize
              → valid/fitness/rmse/TF 检查
              → bz_navigation.launch
              → control.launch（启动急停=True）
              → 遥控器 POSCTL + 解锁
              → make_plan tolerance=0.0
              → 发布单点目标
              → 解除急停，确认 OFFBOARD
              → 监控运行
              → 到点急停，恢复 POSCTL
              → 取消旧目标并正常停机
```
