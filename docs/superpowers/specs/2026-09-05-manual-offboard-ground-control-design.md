# 地面任务手动 OFFBOARD 与 20 Hz 同步控制设计

## 目标

地面自主导航期间，机器人程序不再控制 PX4 的解锁状态或飞行模式。操作者使用遥控器手动解锁、切入 `OFFBOARD`，急停后也手动切回 `POSCTL`。机器人程序只负责检查前置状态、执行导航、输出底盘控制量和锁存急停。

## 范围

- 修改远程 `/home/bitcq/catkin_ws` 中的地面任务控制链。
- 保持现有 ROS 服务和消息类型兼容。
- 将导航控制、速度路由和底盘执行输出统一为 `20 Hz`。
- 在同一条 `mavros_msgs/ActuatorControl` 消息中同时写入前进量和转向量，使 PX4 混控器在同一周期更新左右侧轮。
- 更新《空地两用机器人_地面模态自主导航使用手册_V1.0.md》并同步到 `AADCL/AG-TEST`。
- 不改变飞行任务的起飞、降落和高度接口。

## 控制状态契约

`/ground_air/prepare_ground` 不再调用 MAVROS 解锁服务，也不再调用飞行模式切换服务。它仅在下列条件全部满足时返回成功：

1. 机械模态为地面模态；
2. MAVROS 与飞控连接正常；
3. 飞控已经由操作者手动解锁；
4. 当前飞行模式为 `OFFBOARD`；
5. 重定位有效；
6. 软件急停已经解除。

条件不满足时，接口返回失败及明确原因，不产生任何飞控状态修改。

`/ground_air/emergency_stop` 的行为如下：

- `active: true`：取消当前导航、锁存急停并持续输出零速度；不自动切换 `POSCTL`，操作者必须在遥控器上完成模式切换。
- `active: false`：仅解除软件急停锁存，不自动切换 `OFFBOARD`。重新开始任务前仍由 `/ground_air/prepare_ground` 检查当前是否已手动进入 `OFFBOARD`。

## 20 Hz 数据流

```text
move_base / TEB (20 Hz)
  -> /cmd_vel
  -> ground_air_cmd_vel_router (20 Hz)
  -> /ground/cmd_vel
  -> ground_air_ground_actuator (20 Hz)
  -> /mavros/actuator_control
  -> PX4 mixer
  -> 左右侧轮同步更新
```

底盘执行节点每个周期只发布一条 `ActuatorControl`：`controls[3]` 携带前进量，`controls[2]` 携带反向后的转向量。两项在同一个消息时间点写入和发送，不拆成左右轮两个异步话题，也不猜测飞控内部电机通道映射。

## 错误处理

- 未手动解锁或未进入 `OFFBOARD`：拒绝准备和启动任务，车辆保持停止。
- 急停有效：任务提交或启动失败，持续零输出。
- 指令超时：底盘执行器自动输出零值。
- 模式在任务中被遥控器切离 `OFFBOARD`：任务控制链停止有效运动输出并报告状态异常；不尝试自动切回。

## 测试

1. 单元测试确认地面准备只读检查状态，不调用解锁或模式切换服务。
2. 契约测试确认急停启停路径均不调用飞行模式切换。
3. 启动文件测试确认 `move_base`、速度路由器和底盘执行器均配置为 `20 Hz`。
4. 执行器测试确认单条消息同时包含前进和转向控制量，并且每个定时周期只发布一次。
5. 远程执行相关 Python 测试、Launch XML 检查和 `catkin_make -j1`；不解锁、不发送实车运动任务。

## 操作手册更新

手册明确写出新的人工顺序：启动基础、重定位和任务系统，解除软件急停，遥控器手动解锁并切入 `OFFBOARD`，检查状态后提交任务。急停时先调用软件急停或使用遥控器阻断运动，再由操作者手动切回 `POSCTL`。
