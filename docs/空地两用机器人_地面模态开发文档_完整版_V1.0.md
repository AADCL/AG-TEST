## 2. 总体架构

### 2.1 建图与定位数据流

```text
Livox Mid-360 点云和 IMU
        │
        ▼
livox_ros_driver2
        │ /livox/lidar、/livox/imu
        ▼
FAST-LIO（fast_lio_open3d）
        ├── /cloud_registered       camera_init 下注册点云
        ├── /cloud_registered_body  body 下实时障碍点云
        ├── /Odometry               camera_init → body 局部里程计
        └── TF camera_init → body
             │
             ├── 建图：ground_air_mapping + /map
             └── 重定位：ground_air_localization + 历史 cloud_map.pcd
```

2026-08-28 已把 FAST-LIO 自定义后缀恢复为上游接口：`/Laser_map`、`/Odometry`、`/cloud_effected`、`/cloud_registered`、`/cloud_registered_body`。所有建图、重定位、TEB、costmap、PX4 适配、平台和融合客户端消费者已同步修改。`/air/cmd_vel` 与 `/body_frame/path` 是独立功能接口，保持不变。旧进程不会热更新，必须重启相应启动栈后新名称才生效。

### 2.2 地面导航与执行数据流

```text
历史 /map + map 位姿 + 实时障碍点云
        │
        ▼
move_base
  ├── GlobalPlanner：全局路径
  └── TEB：局部轨迹和实时避障
        │ /navigation/cmd_vel
        ▼
ground_air_cmd_vel_router
        │ /ground/cmd_vel
        ▼
ground_air_ground_actuator
        │ /mavros/actuator_control
        ▼
MAVROS → PX4 → 地面执行机构
```

### 2.3 安全边界

- 所有总启动文件保持被动：不自动解锁、不自动起飞、不自动降落、不自动切换机械模态。
- 建图时车辆运动只由遥控器负责，软件控制、导航和任务执行器默认关闭。
- 重定位有效前禁止自主导航和任务执行。
- 软件急停是 ROS/PX4 控制链的安全闭锁，不能替代遥控器、现场安全员和物理断电。
- 地面执行器直接控制只在 PX4 `OFFBOARD` 下生效；操作者仍使用遥控器完成解锁。

## 4. 启动层设计

### 4.1 三个正式操作入口

2026-08-28 新增三个面向操作者的一键 launch：

| Launch | 必填参数 | 默认行为 |
|---|---|---|
| `car_bringup/start_mapping.launch` | `map_id` | 启动手控建图基础栈，并在服务就绪后自动调用 `/ground_air/mapping/start` |
| `car_bringup/save_mapping.launch` | 无 | 调用 `/ground_air/mapping/save`，打印真实保存结果后退出 |
| `car_bringup/start_relocalization.launch` | `map_id` | 启动仅定位基础栈，自动加载地图并以完全未知位姿执行全局重定位 |

三个入口都保持被动，不解锁、不发送速度、不起飞、不降落。`start_mapping.launch` 默认 `start_mavros=true`；`start_relocalization.launch` 默认 `start_mavros=false`，且强制关闭导航、控制和任务执行器。两个启动型入口默认 `start_stack=true` 并在操作成功后保持基础栈运行；若基础栈已由外部启动，可传 `start_stack:=false` 仅执行一次服务操作。

`ground_air_operation_node.py` 是这三个 launch 共用的操作适配器，负责等待服务、转发 `map_id`、检查返回值，以及在失败时令 required 节点退出，使 roslaunch 能反映真实失败。

```bash
roslaunch car_bringup start_mapping.launch map_id:=site_20260828_01
roslaunch car_bringup save_mapping.launch
roslaunch car_bringup start_relocalization.launch map_id:=site_20260826_01
```

### 4.2 `manual_mapping.launch`

手控建图底层入口。通常由 `start_mapping.launch` 包含；它本身只拉起基础栈，不自动开始记录。它包含 `ground_air_full.launch`，并明确：

- `start_mavros=true`
- `start_fastlio_odometry_to_px4=true`
- `start_dynamic_mapping=true`
- `start_localization=false`
- `start_navigation=false`
- `start_control=false`
- `start_mission=false`
- `start_vision_to_mavros=false`
- `start_fusion_client=true`

随后包含 `ground_air_mapping/mapping.launch`。因此建图期间 ROS 只感知和记录，车辆由遥控器驾驶。

### 4.3 `autonomy.launch`

自主模式安全入口，默认只启用定位基础能力：

```text
start_mavros=false
start_navigation=false
start_control=false
start_mission=false
```

这种默认值允许先完成地图加载、重定位和接口检查，再分终端显式启动导航与控制。

### 4.4 `ground_air_full.launch`

统一组合入口，参数控制 MAVROS、Livox、FAST-LIO、地面过滤、动态建图、定位、导航、控制、任务和融合客户端。该 launch 自身不发送运动命令。

需要注意：它的部分通用参数默认值会启用导航、控制和任务；实机调试优先从 `autonomy.launch` 或文档给出的显式参数启动，不应直接依赖通用默认值。

### 4.5 `bz_navigation.launch`

地面规划与避障入口：

- 全局规划器：`global_planner/GlobalPlanner`
- 局部规划器：`teb_local_planner/TebLocalPlannerROS`
- `/cmd_vel` 重映射为 `/navigation/cmd_vel`
- `planner_frequency=1.0 Hz`
- `controller_frequency=5.0 Hz`
- `recovery_behavior_enabled=false`
- `clearing_rotation_allowed=false`

`enable_drone_mode` 默认为 `false`。地面测试不得把该参数改为 `true`。

## 5. 坐标系与 TF 所有权

### 5.1 主 TF 树

```text
map
└── odom
    └── camera_init
        └── body
            └── base_link
```

坐标系语义：

| frame | 语义 |
|---|---|
| `map` | 已保存历史地图和全局任务坐标系 |
| `odom` | PX4/MAVROS 本次运行的局部里程计坐标系 |
| `camera_init` | FAST-LIO 本次启动的局部里程计起始坐标系 |
| `body` | FAST-LIO 机体坐标系 |
| `base_link` | 地面导航、footprint 和控制基座坐标系 |

`map` 不是机器人机体；机器人机体对应 `body`，地面导航基座对应 `base_link`。Livox 数据直接标记为 `base_link`，不再建立独立雷达 frame。

### 5.2 唯一发布者

| TF 边 | 类型 | 唯一发布者/来源 |
|---|---|---|
| `map → odom` | 动态或模式相关 | `ground_air_world_tf_owner` |
| `odom → camera_init` | 静态恒等 | `odom_camera_init_broadcaster` |
| `camera_init → body` | 动态 | FAST-LIO `laserMapping` |
| `body → base_link` | 静态 | 机器人安装外参发布器 |

建图模式中 `map → odom` 为恒等变换；自主模式中仅在 `/ground_air/localization/valid=True` 时发布 Open3D 解算结果。`odom → camera_init` 暂按已验证的共同启动原点发布静态恒等变换。系统禁止重新引入 `world`、`livox_frame` 或重复 TF 发布者。

`fastlio_odometry_adapter.py` 为 MAVROS 改写 Odometry 消息的 frame 名为 `odom/base_link`，让 MAVROS 完成 ENU/FLU 到 NED/FRD 的标准转换。该消息适配器本身不发布 ROS TF；`odom → camera_init` 由唯一静态发布器负责。

### 5.3 无界面 TF 导出

`car_bringup/scripts/export_tf_tree.py` 同时监听 `/tf` 和 `/tf_static`，校验四条目标边、child 唯一 parent 和无旧 `odom` 链，然后运行 `rosrun tf view_frames`。输出：

```text
/home/bitcq/catkin_ws/artifacts/tf/<时间戳>/frames.gv
/home/bitcq/catkin_ws/artifacts/tf/<时间戳>/frames.pdf
```

## 6. 手控建图实现

### 6.1 公共接口

```text
/ground_air/mapping/start   ground_air_msgs/StartMapping
/ground_air/mapping/save    ground_air_msgs/SaveMapping
/ground_air/mapping/cancel  std_srvs/Trigger
/ground_air/mapping/status  ground_air_msgs/MappingStatus
```

`MappingStatus` 状态为 `IDLE=0`、`RECORDING=1`、`SAVING=2`、`COMPLETE=3`、`ERROR=4`。

### 6.2 记录策略

- 输入注册点云：`/cloud_registered`，预期 frame 为 `camera_init`。
- 输入二维地图：`/map`。
- 以 `0.10 m` 体素哈希在线累计点云，抑制重复点。
- 记录容量上限为 500 万点，避免长期建图耗尽内存。
- `map_id` 只允许字母、数字、点、下划线和连字符，最长 64 字符。
- 已存在的同名地图拒绝覆盖。
- `cancel` 只清理当前未保存缓存，不删除历史地图。

### 6.3 原子地图包

保存时先写临时目录，完成 PCD/PGM/YAML/元数据校验后再原子改名：

```text
/home/bitcq/catkin_ws/maps/<map_id>/
├── cloud_map.pcd
├── map.pgm
├── map.yaml
└── metadata.json
```

其中 PCD 用于三维重定位，PGM/YAML 用于 map_server 和二维导航，metadata 保存地图 ID、点数、面积等信息。缺少点云、图像、YAML 或 YAML 图片引用错误时，地图加载必须失败。

## 7. PX4 Position 所需里程计适配

FAST-LIO 原始里程计：

```text
/Odometry
header.frame_id = camera_init
child_frame_id = body
```

建图入口中的 `fastlio_odometry_adapter.py` 校验上述 frame，复制位姿和协方差，只将消息语义 frame 改写为：

```text
/mavros/odometry/out
header.frame_id = odom
child_frame_id = base_link
```

MAVROS 自己完成 ENU/FLU → NED/FRD 的数值转换。上游不得再旋转一次，否则会产生双重转换。此适配解决了 MAVROS 试图查询 `odom_ned` 与 `camera_init` 不在同一 TF 树的问题，同时保持 ROS 主 TF 树干净。

## 8. 地图管理和全局重定位

### 8.1 地图管理

`ground_air_map_manager` 提供 `/ground_air/load_map`：

1. 校验 `map_id` 和本地路径；
2. 要求地图包恰有一个 PCD、一个 YAML，且 YAML 图片在包目录内；
3. 必要时通过临时目录原子安装；
4. 启动 `map_server`，以 `map` 发布 `/map`；
5. 设置 `/ground_air/active_map_*` 参数；
6. 发布 `/ground_air/localization/map_changed`；
7. 明确返回“地图已激活，但必须重新定位”。

默认只加载车载本地图库，不实现平台 HTTP 地图下载。

地图激活后，通过 `/ground_air/relocalize`（`ground_air_msgs/Relocalize`）执行全局重定位；加载成功本身不代表机器人已经定位。

### 8.2 未知位姿全局解算

`ground_air_global_relocalizer` 默认订阅：

```text
/cloud_registered
/Odometry
/ground_air/localization/map_changed
```

每次定位累计至少 5 帧、最长 3 秒的局部点云。`use_initial_guess=false` 时：

1. 对历史地图和实时局部点云降采样；
2. 计算法线和 FPFH 特征；
3. 使用特征匹配 RANSAC 进行全局粗配准；
4. 使用点到面 ICP 精配准；
5. 独立重复全局求解，避免对称场景的错误结果自我确认；
6. 连续两次质量和一致性均通过后才置定位有效。

因此完全未知初始位姿不需要操作者在 RViz 给出位置和朝向。

### 8.3 质量门限

| 参数 | 当前值 |
|---|---:|
| `min_fitness` | 0.55 |
| `max_rmse` | 0.30 m |
| `required_confirmations` | 2 |
| 两次最大位移差 | 0.50 m |
| 两次最大角度差 | 0.35 rad |
| 点云过期时间 | 2.0 s |
| 跟踪失败上限 | 3 次 |
| 默认服务超时 | 60 s |

成功后以 1 Hz 低频 ICP 跟踪。地图切换、连续 3 次跟踪失败或点云过期会把定位置为无效，并停止刷新有效全局 TF。

## 9. 地面全局规划与实时避障

### 9.1 GlobalPlanner

`global_planner_params.yaml` 定义全局栅格搜索行为。当前关键值：

| 参数 | 值 | 含义 |
|---|---:|---|
| `use_dijkstra` | true | 使用 Dijkstra 势场搜索 |
| `use_quadratic` | true | 二次势场近似 |
| `allow_unknown` | false | 不穿越未知区 |
| `default_tolerance` | 0.25 m | 规划器默认邻近容差 |
| `lethal_cost` | 253 | 致命代价值 |
| `neutral_cost` | 50 | 中性代价 |
| `cost_factor` | 3.0 | 代价缩放 |
| `orientation_mode` | 1 | 路径方向生成方式 |

实机目标准入必须额外调用 `/move_base/make_plan` 且使用 `tolerance: 0.0`。这比规划器内部 `default_tolerance` 更严格，防止目标落在墙体、地图边界或膨胀区时被悄悄替换为邻近点。

### 9.2 Costmap

| 项目 | 当前值 |
|---|---|
| footprint | `[[0.3,0.3],[0.3,-0.3],[-0.3,-0.3],[-0.3,0.3]]` |
| 障碍点云 | `/cloud_registered_body` |
| 障碍/射线清除距离 | 5.0/6.0 m |
| 障碍高度范围 | 0.15～2.1 m |
| 障碍观察保持 | 1.0 s |
| 膨胀半径 | 0.6 m |
| 膨胀衰减 | 10.0 |
| 全局静态地图 | `/map` |

全局 costmap 组合历史地图、实时点云和膨胀层；局部 costmap 使用实时障碍与膨胀层，不重复加载静态层。

当前规划足迹为 `0.6 × 0.6 m`，半长和半宽均为 `0.30 m`。全局 costmap、局部 costmap、兼容 costmap 与 TEB polygon 已统一。该值缩小了规划器使用的占地范围；如果机器人真实最大外廓大于 `0.6 × 0.6 m`，规划结果可能低估擦碰风险，实机必须保留额外人工安全余量。YAML 修改后必须重启 `move_base`。

### 9.3 TEB 保守参数

| 参数 | 当前值 |
|---|---:|
| `max_vel_x` | 0.1 m/s |
| `max_vel_x_backwards` | 0.1 m/s |
| `max_vel_theta` | 0.2 rad/s |
| `acc_lim_x` | 0.05 m/s² |
| `acc_lim_theta` | 0.2 rad/s² |
| `xy_goal_tolerance` | 0.25 m |
| `yaw_goal_tolerance` | 0.35 rad |
| `min_obstacle_dist` | 0.3 m |
| `inflation_dist` | 0.3 m |

TEB 使用 costmap 障碍，动态障碍速度估计尚未接入，因此 `include_dynamic_obstacles=false`；这不等于没有实时避障，实时点云仍通过 costmap 生效。

当前仍观察到障碍附近局部轨迹左右摆动、走走停停的现象。该问题尚未调参闭环，不应通过提高速度、关闭障碍层或继续缩小 footprint 规避。

### 9.4 高速原地旋转事件

一次实机测试出现高速原地转圈。根因不是“未重定位”这一单一因素，而是旧的运行中 `move_base` 仍加载旋转恢复，同时目标/朝向条件不安全。修复后：

- 禁用 `recovery_behavior_enabled`；
- 禁用 `clearing_rotation_allowed`；
- 重启 `move_base` 使插件配置生效；
- 导航前确认重定位、真实车头方向和精确终点路径；
- 首次目标限制为 0.5～1.0 m。

### 9.5 2026-08-28 实机导航结论

- 单点自主导航与实时避障已完成一次明确成功测试，可继续按低速、短距离、有人监护流程复测。
- 多点测试曾在障碍环境发生碰撞，不能标记为通过。
- “前进 5 m，再回到起点且朝向相反”的第二任务点返回 `move_base status=4 (ABORTED)`，mission 状态为 `state=5 (FAILED)`；现场存在可通道路段不等于局部规划、终点姿态和 costmap 同时可行。
- 障碍附近存在左右修正振荡，后续需要结合全局路径、局部轨迹、local costmap 与 TEB 优化状态逐帧诊断。

## 10. 地面控制、安全闭锁与 PX4

### 10.1 速度路由

`ground_air_cmd_vel_router` 订阅 `/navigation/cmd_vel` 和 `/ground_air/vehicle_status`。只有地面模态、定位和安全状态满足条件时，才把速度送至 `/ground/cmd_vel`；急停、未知模态、切换中和输入超时均输出零。

### 10.2 地面执行器

`ground_air_ground_actuator` 以 20 Hz 发布 `mavros_msgs/ActuatorControl`：

```text
group_mix = 1
controls[3] = clamp(linear.x, -1, 1)
controls[2] = clamp(-angular.z, -1, 1)
```

其内部还对速度归一化并执行 0.5 s 指令超时保护。导航速度上限由 TEB 保守参数限制，执行器的较大物理归一化上限不是允许导航高速运行的依据。

### 10.3 模式管理和急停

`ground_air_mode_manager` 启动时立即：

```text
emergency_stop = True
detail = startup safety interlock
```

地面软件急停公共服务为 `/ground_air/emergency_stop`（`ground_air_msgs/SetEmergencyStop`）。

地面构型且已由遥控器解锁时，解除急停会先请求 PX4 `OFFBOARD` 并确认，再允许速度通过。重新激活急停会先输出零、等待执行器归零，再请求恢复 `POSCTL`。

成功消息：

```text
operator reset; ground OFFBOARD confirmed
operator emergency stop; POSCTL restored
```

服务失败时保持停止，不能连续盲目重试。软件代码不得主动解锁飞控。

## 11. 有序多点任务

`ground_air_mission` 已提供：

```text
/ground_air/mission/submit
/ground_air/mission/start
/ground_air/mission/pause
/ground_air/mission/resume
/ground_air/mission/cancel
/ground_air/mission/status
```

设计规则：

- 接受 `map` 下的一组有序 `PoseStamped`；
- 未定位或急停激活时拒绝任务；
- 依次调用 `/move_base` Action；
- 地面模态每个任务点到达后停留 2 秒；
- 暂停、取消、失败和定位失效都必须发停止；
- 本功能已开始实机测试但未通过，修复和重新验收前不得用于常规任务。

已知失败证据：

- 障碍环境多点任务发生过碰撞；
- 掉头返回任务在第二点返回 `move_base status=4`，任务状态持续为 `state=5`；
- 失败并不能仅归因于“没有路”，还需要检查精确终点、终点朝向、footprint、膨胀区、局部轨迹和 TEB 可行性。

## 15. 已知限制和禁止事项

- 静态外参暂沿用现值，物理外参标定是独立后续任务。
- 无 GUI 不影响 ROS 运行，可用 `view_frames`、话题和地图文件离线查看。
- 完全未知位姿重定位在低重叠、对称、动态变化大或雷达遮挡场景可能失败。
- 地图中的未知区、边界和膨胀区即使现场看似可通行，也不能作为导航目标。
- 不得启动第二套 Livox、FAST-LIO、`move_base` 或 `map → odom` 发布者。
- 不得重新引入 `world`、`livox_frame` 或第二个 `odom → camera_init` 发布者。
- 不得在未定位、未做精确路径检查或无人监护时解除软件急停。
- `0.6 × 0.6 m` 是规划配置值，不自动证明等于机器人真实最大外廓；未完成实测外廓复核前必须扩大人工安全距离。
- 多点任务和掉头返回任务当前属于“实机测试未通过”，不得按已验证功能使用。
- 障碍附近出现左右摆动或连续停顿时必须停止测试，不得通过提高速度继续试跑。
- 不得依据本文测试飞行、自动起降或飞行模态切换。
