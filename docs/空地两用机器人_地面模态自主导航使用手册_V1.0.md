## 2. 安全红线

- 现场必须有能立即操作遥控器的人，周围不得有人靠近车轮和桨叶。
- ROS 不负责解锁；只用遥控器按现有安全规程解锁。
- ROS 不再替遥控器切换 `OFFBOARD` 或 `POSCTL`；这两个模式必须由操作者手动选择。
- 建图时不启动导航、控制和任务执行器。
- `/ground_air/localization/valid` 不是 `True` 时禁止自主移动。
- 下发目标前必须用 `/move_base/make_plan` 做 `tolerance: 0.0` 的精确检查。
- 第一次目标只设 0.5～1.0 m，不直接进行 6 m 长距离测试。
- 当前规划 footprint 为 `0.6 × 0.6 m`；在未确认真实最大外廓前，必须额外扩大与墙体、桌腿和人员的距离。
- 出现高速旋转、方向相反、障碍判断异常或人员进入区域时，立即遥控器接管并急停。
- 障碍附近出现连续左右摆动、走走停停或路径贴障时，立即终止，不得提高速度继续。
- 软件急停不能替代遥控器和物理断电。
- 本手册不允许进行飞行、自动起降或空中模态切换。

## 5. 手控建图全流程

### 5.1 启动建图

为本次地图选择一个从未使用过的 `map_id`。终端一执行正式入口：

```bash
cd ~/catkin_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash
roslaunch car_bringup start_mapping.launch map_id:=site_20260828_01
```

该入口会启动 MAVROS、Livox、FAST-LIO、动态二维地图、地图记录器和 FAST-LIO→MAVROS 里程计适配，并在记录服务就绪后自动开始本次地图。它不会启动软件导航和地面执行器，也不会解锁车辆。

成功标志：

```text
ground-air operation 'start_mapping' succeeded: recording registered point cloud and occupancy map
```

该 launch 在成功后会继续运行，用于维持建图基础栈。不要关闭终端一。

### 5.2 检查输入

终端二：

```bash
cd ~/catkin_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash

rostopic echo -n1 /cloud_registered/header
rostopic echo -n1 /Odometry/header
rostopic hz /cloud_registered
rostopic hz /Odometry
```

两个 header 的 `frame_id` 都应为 `camera_init`。

如需 PX4 Position 模式，再检查：

```bash
rostopic hz /mavros/odometry/out
rostopic echo -n1 /mavros/odometry/out/header
rostopic echo -n1 /mavros/state
```

`/mavros/odometry/out` 应持续更新。MAVROS 负责 ENU/FLU 到 NED/FRD 的转换，不需要操作者再做坐标转换。

### 5.3 确认已经开始记录

`start_mapping.launch` 已经自动调用开始记录服务，不需要再手动调用 `/ground_air/mapping/start`。用下面的状态话题确认：

```bash
rostopic echo -n1 /ground_air/mapping/status
```

`state: 1` 且 `map_id` 与启动参数一致，表示本次地图已经开始建立；刚开始 `point_count: 0` 属于正常现象。只有在已有建图基础栈、并明确使用 `start_stack:=false` 的维护场景中，才直接调用底层服务。

### 5.4 观察状态

```bash
rostopic echo /ground_air/mapping/status
rostopic hz /map
```

| state | 含义 |
|---:|---|
| 0 | 空闲 |
| 1 | 正在记录 |
| 2 | 正在保存 |
| 3 | 保存完成 |
| 4 | 错误 |

### 5.5 遥控器驾驶

- 切到地面构型，低速、平稳驾驶。
- 沿边界走一圈，再覆盖内部通道。
- 从不同方向观察墙角、门口、立柱和走廊。
- 相邻路线保留重叠，避免急转、急停和原地高速旋转。
- 尽量形成闭环并回到起点附近。
- 建图期间不要停止 Livox、FAST-LIO 或建图 launch。

### 5.6 保存地图

停车并保持静止。终端二执行正式保存入口：

```bash
roslaunch car_bringup save_mapping.launch
```

保存 launch 会调用真实服务并退出。输出中应有：

```text
success: True
map_directory: "/home/bitcq/catkin_ws/maps/<map_id>"
point_count: <大于0>
```

检查四个地图文件：

```bash
ls -lh /home/bitcq/catkin_ws/maps/<map_id>/
```

必须包含：

```text
cloud_map.pcd
map.pgm
map.yaml
metadata.json
```

确认保存成功后，再在终端一按一次 `Ctrl+C`，等待 launch 正常退出。不要 `kill -9`，也不要在保存过程中直接断电。

### 5.7 取消未保存地图

仅当确认不要本次缓存时：

```bash
rosservice call /ground_air/mapping/cancel "{}"
```

它不会删除已经保存的历史地图。

### 5.8 复制到 Windows 查看

在 Windows PowerShell 执行：

```powershell
$mapId = "site_20260828_01"
$dst = "$env:USERPROFILE\Desktop\$mapId"
New-Item -ItemType Directory -Force -Path $dst | Out-Null
scp "bitcq@192.168.50.130:/home/bitcq/catkin_ws/maps/$mapId/*" "$dst\"
```

- `map.pgm`：普通二维图片或图像工具查看。
- `cloud_map.pcd`：CloudCompare、Open3D 或 PCL 工具查看。
- 无图形界面不影响车端建图和保存。

## 6. 未知初始位姿重定位

### 6.1 准备

1. 先停止 `start_mapping.launch`，确认地图保存过程已经结束。
2. 确认没有第二套 Livox、FAST-LIO 或定位 launch。
3. 把机器人放在历史地图覆盖区域，优先选择墙角、立柱等结构明显位置。
4. 保持雷达无遮挡，重定位期间机器人静止。

### 6.2 启动自主基础栈

终端一执行正式重定位入口：

```bash
cd ~/catkin_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash

roslaunch car_bringup start_relocalization.launch \
  map_id:=site_20260826_01 \
  start_mavros:=false
```

该入口启动 Livox、FAST-LIO、地图管理和全局重定位，强制关闭导航、控制与任务执行器；随后自动加载指定地图并执行完全未知位姿重定位。它不产生地面运动指令，也不会解锁车辆。若现场没有其他 MAVROS 实例且确实需要 MAVROS 状态，可改为 `start_mavros:=true`，但禁止重复启动 MAVROS。

### 6.3 检查输入

```bash
rostopic echo -n1 /cloud_registered/header
rostopic echo -n1 /Odometry/header
timeout 8 rostopic hz /cloud_registered
timeout 8 rostopic hz /Odometry
```

两者必须持续更新，frame 为 `camera_init`。

### 6.4 确认地图已加载

`start_relocalization.launch` 已自动调用 `/ground_air/load_map`，无需再次手动加载。地图加载失败时该 launch 会报错退出；最终重定位成功也意味着前置地图加载已经成功。

检查 `/map`：

```bash
rostopic echo -n1 /map/header
```

预期 `frame_id: "map"`。

### 6.5 等待全局重定位

该 launch 会继续自动调用 `/ground_air/relocalize`，参数等价于 `use_initial_guess=false`、`timeout=60.0`。算法会在历史点云中自动寻找位置和朝向，因此不需要操作者输入初始位姿。机器人保持静止，最长等待 60 秒。成功后基础栈继续运行，导航期间不要关闭终端一。

成功日志应包含：

```text
ground-air operation 'relocalize' succeeded: global relocalization confirmed on consecutive scans
fitness=<数值> rmse=<数值> pose=(<x>, <y>, <z>)
```

### 6.6 判断成功

```bash
rostopic echo -n1 /ground_air/localization/valid
rostopic echo -n1 /ground_air/localization/fitness
rostopic echo -n1 /ground_air/localization/rmse
rostopic echo -n1 /ground_air/localization/pose
rosrun tf tf_echo map odom
rosrun tf tf_echo odom camera_init
```

必须同时满足：

```text
valid = True
fitness >= 0.55
rmse <= 0.30 m
pose.header.frame_id = map
map -> odom 持续可查询
```

系统完整主 TF 链应为：

```text
map → odom → camera_init → body → base_link
```

已验证结果约为 `fitness=1.0`、`rmse=0.041 m`。单次结果不代表全部场景均已验收，建议同点重启重复 3 次，再在相隔 2～5 m 且改变朝向的位置测试。

## 7. 地面单点自主导航与避障

本章沿用此前在远程主机上完成实车短距离导航测试的服务流程。只能在第 6 章重定位成功后执行，所有任务点必须使用 `map` 坐标系，不能把相对位移直接写成 `base_link` 目标。

### 7.1 启动完整任务层

保持 `base_system.launch` 和 `start_relocalization.launch` 两个终端继续运行。在新终端启动任务、规划和控制：

```bash
cd ~/catkin_ws
source /opt/ros/noetic/setup.bash
source devel/setup.bash
roslaunch car_bringup task_system.launch start_ccs_task_adapter:=false
```

该入口统一启动 `move_base`、TEB、速度路由器、地面执行器和 `ground_air_mission`。不要再单独重复启动 `bz_navigation.launch` 或 `control.launch`。

检查 20 Hz 控制链：

```bash
rosparam get /move_base/controller_frequency
rosparam get /ground_air_cmd_vel_router/rate
rosparam get /ground_air_ground_actuator/rate
```

三项都应为 `20.0`。地面执行器每个周期只发布一条 `/mavros/actuator_control`，其中前进量和转向量同时写入，由 PX4 混控器同步生成左右侧轮控制。

检查保守规划和实时避障输入：

```bash
rosparam get /move_base/recovery_behavior_enabled
rosparam get /move_base/clearing_rotation_allowed
rosparam get /move_base/TebLocalPlannerROS/max_vel_x
rosparam get /move_base/TebLocalPlannerROS/max_vel_theta
timeout 8 rostopic hz /cloud_registered_body
rosparam get /move_base/global_costmap/footprint
rosparam get /move_base/local_costmap/footprint
```

恢复旋转应为 `false`，三处足迹应对应 `0.6 × 0.6 m`。实时局部避障继续使用 `/cloud_registered_body`，不是使用保存地图中的动态点。

### 7.2 遥控器手动交接控制权

任务系统启动后软件急停默认不锁定。先确认执行器为零，并检查当前状态：

```bash
rostopic echo -n1 /ground_air/vehicle_status
rostopic echo -n1 /mavros/actuator_control
```

随后由现场操作者使用遥控器完成以下动作：

1. 确认机械结构处于地面模态；
2. 手动解锁；
3. 手动把飞控模式切换到 `OFFBOARD`。

检查真实反馈：

```bash
rostopic echo -n1 /mavros/state
rostopic echo -n1 /mavros/extended_state
```

必须看到 `connected: True`、`armed: True`、`mode: "OFFBOARD"`，并确认地面构型。程序不会替遥控器完成解锁或模式切换。

正常情况下应看到 `emergency_stop: False`，不再需要每次启动都调用解除服务。若现场状态仍为 `True`，先查明是否由操作者、平台或显式启动参数触发；确认允许恢复后再调用：

```bash
rosservice call /ground_air/emergency_stop "active: false"
```

成功响应中的提示应包含：

```text
operator reset; manually arm and select OFFBOARD before ground preparation
```

再执行只读准备检查：

```bash
rosservice call /ground_air/prepare_ground "{}"
```

必须返回：

```text
success: True
message: "ground navigation ready"
```

如果未解锁、未进入 `OFFBOARD`、重定位无效或仍有急停，准备服务会拒绝任务，不会自动改变飞控状态。

### 7.3 计算并检查目标

读取重定位后的当前位置：

```bash
rostopic echo -n1 /ground_air/localization/pose
```

向机体正前方移动 `d` 米时，先根据当前 `map` 位姿计算绝对目标：

```text
目标X = 当前X + d × cos(当前yaw)
目标Y = 当前Y + d × sin(当前yaw)
目标朝向 = 当前朝向
```

首次测试令 `d=0.50`。将算出的数值代入精确路径检查：

```bash
rosservice call /move_base/make_plan "
start:
  header: {frame_id: 'map'}
  pose:
    position: {x: <当前X>, y: <当前Y>, z: 0.0}
    orientation: {x: <当前QX>, y: <当前QY>, z: <当前QZ>, w: <当前QW>}
goal:
  header: {frame_id: 'map'}
  pose:
    position: {x: <目标X>, y: <目标Y>, z: 0.0}
    orientation: {x: <当前QX>, y: <当前QY>, z: <当前QZ>, w: <当前QW>}
tolerance: 0.0"
```

只有 `plan.poses` 非空才继续。目标位于未知区、墙体、地图边界或膨胀区时，重新选点。

### 7.4 通过任务服务下发并启动

按此前远程实测使用的接口提交单点任务：

```bash
rosservice call /ground_air/mission/submit "
mission_id: 'forward_0p5_test'
goals:
- header:
    frame_id: 'map'
  pose:
    position: {x: <目标X>, y: <目标Y>, z: 0.0}
    orientation: {x: <当前QX>, y: <当前QY>, z: <当前QZ>, w: <当前QW>}"
```

必须返回 `accepted: True`、`goal_count: 1`。然后启动：

```bash
rosservice call /ground_air/mission/start "{}"
```

预期返回：

```text
success: True
message: "navigating to goal 0"
```

### 7.5 运行监控

```bash
rostopic echo /ground_air/mission/status
rostopic echo /ground_air/localization/valid
rostopic echo /ground_air/vehicle_status
rostopic echo /move_base/status
rostopic echo /navigation/cmd_vel
```

任务状态：`0=空闲`、`1=执行中`、`2=到点停留`、`3=暂停`、`4=成功`、`5=失败`、`6=取消`、`7=等待降落`。单点地面任务正常结束应为 `state: 4`。

飞控被遥控器切离 `OFFBOARD` 时，速度路由器立即停止地面指令，不会自动切回；操作者应取消任务、确认环境，再决定是否重新进入 `OFFBOARD`。

### 7.6 到点与正常停止

任务显示 `state: 4` 后立即锁存软件急停：

```bash
rosservice call /ground_air/emergency_stop "active: true"
```

然后由操作者在遥控器上手动切回 `POSCTL`。确认：

```bash
rostopic echo -n1 /ground_air/vehicle_status
rostopic echo -n1 /mavros/state
rostopic echo -n1 /mavros/actuator_control
```

应看到 `emergency_stop: True`、`mode: "POSCTL"`，执行器前进和转向控制量均为零。软件急停不会替遥控器切换 `POSCTL`。

### 7.7 指控平台选点下发自主导航

当前机器人侧已经具备指控平台任务适配链。指控平台在已加载的二维地图上选点后，必须把点转换成 `map` 坐标系下的绝对坐标，并生成机器人可读取的轨迹 XML；机器人不直接从任务消息字段中读取 `x/y`。

完整数据流为：

```text
指控平台地图选点
        ↓
生成 schema_version=2 的轨迹 XML
        ↓
将 XML 放入机器人允许的 mission_root
        ↓
/epgeneral_task_control/execution_command（PREPARE）
        ↓
校验文件、任务身份、map_id、frame_id、定位和车辆状态
        ↓
/ground_air/mission/submit
        ↓
/epgeneral_task_control/execution_command（SCHEDULE）
        ↓
/ground_air/prepare_ground → /ground_air/mission/start
        ↓
move_base 全局规划 + 实时点云局部避障
        ↓
/navigation/cmd_vel → 20 Hz 控制链 → 左右侧轮
        ↓
/epgeneral_task_control/execution_feedback
```

启动任务层时必须显式开启 CCS 适配器：

```bash
roslaunch car_bringup task_system.launch \
  start_ccs_task_adapter:=true \
  ccs_mission_root:=/home/bitcq/ccs_edge_ws/mission
```

启动后检查：

```bash
rosnode info /epaguav_ground_air_task_adapter
rostopic info /epgeneral_task_control/execution_command
rostopic info /epgeneral_task_control/execution_feedback
rosservice info /ground_air/mission/submit
rosservice info /ground_air/mission/start
```

地面任务 XML 示例：

```xml
<?xml version="1.0" encoding="utf-8"?>
<trajectory schema_version="2" task_id="ground-nav-001"
            subtask_id="segment-001" device_id="AGV_001"
            revision="1" crc32="0">
  <metadata task_name="platform-selected-ground-goal"
            map_id="site_20260826_01" frame_id="map"
            cruise_speed_mps="0.3" start_delay_seconds="0.0"
            task_type="GROUND_NAV" sequence_id="ground-seq-001"
            sequence_index="0" sequence_terminal="true" />
  <waypoints count="2">
    <waypoint index="0" waypoint_id="start"
              x="&lt;当前map.x&gt;" y="&lt;当前map.y&gt;" z="0.0" />
    <waypoint index="1" waypoint_id="goal"
              x="&lt;平台选点map.x&gt;" y="&lt;平台选点map.y&gt;" z="0.0" />
  </waypoints>
</trajectory>
```

注意：当前 XML 校验要求导航任务包含 `2～500` 个航点。因此单个终点任务也应写入“当前点 + 目标点”两项；机器人会根据相邻点自动计算航向。XML 必须是 `mission_root` 内的普通文件，不能是符号链接，也不能使用目录外路径。

指控平台发送的 `TaskExecutionCommand` 至少应保证以下字段与 XML 完全一致：

```text
action       PREPARE(4)，校验成功后再发送 SCHEDULE(1)
task_id      与 trajectory.task_id 一致
subtask_id   与 trajectory.subtask_id 一致
device_id    与 trajectory.device_id 一致
revision     与 trajectory.revision 一致
xml_path     XML 在机器人上的完整路径
frame_id     map
map_id       与 metadata.map_id 及当前加载地图一致
execution_id 本次执行的唯一标识
```

平台选点任务执行前仍必须满足：重定位有效、车辆处于地面构型、操作者已手动解锁并切入 `OFFBOARD`、软件急停为 `False`。适配器只负责转换任务和调用现有服务，不负责网络设备接入，不会自动解锁或替遥控器切换飞控模式。

若指控平台当前只实现了图形界面选点，但尚未实现 XML 落盘和 `PREPARE/SCHEDULE` 发布，则机器人不会开始移动；这属于平台侧尚未接通，而不是机器人导航链缺失。

## 8. 紧急停止

### 8.1 车辆异常运动

优先使用遥控器安全开关并手动切回 `POSCTL`，同时执行：

```bash
rosservice call /ground_air/emergency_stop "active: true"
rosservice call /ground_air/mission/cancel "{}"
```

不要等待日志，不要继续观察车辆是否会自己恢复。

### 8.2 正常取消任务

```bash
rosservice call /ground_air/mission/cancel "{}"
rosservice call /ground_air/emergency_stop "active: true"
```

无论哪种停止方式，都要取消旧任务，并由操作者手动切回 `POSCTL`，避免以后解除急停时旧目标继续执行。

## 9. 有序多点任务的当前边界

`ground_air_mission` 已经有提交、启动、暂停、恢复、取消和状态接口，设计为按顺序到达任务点，并在每个地面任务点停留 2 秒。但 2026-08-28 的实机测试没有通过：一次任务与障碍发生碰撞；“前进 5 m，再返回起点并反向”的第二点出现 mission `state=5`、move_base `status=4 (ABORTED)`。

因此：

- 日常实机操作仍使用已验证的单点流程；
- 多点任务当前属于失败项，不得作为可用功能交付或无人看守运行；
- 不在人员和障碍复杂区域直接试跑多点任务；
- 后续测试必须逐点核对地图坐标、零容差路径和急停能力；
- 每个任务点都要分别执行 `make_plan tolerance=0.0`，并检查终点朝向和足迹膨胀区；
- 本手册不提供飞行任务点和起降操作。

## 10. 正常停机顺序

1. 调用 `/ground_air/mission/cancel` 取消当前任务。
2. 激活软件急停并确认执行器全零。
3. 使用遥控器手动切回 `POSCTL` 并按现场规程上锁。
4. 在 `task_system.launch` 终端按 `Ctrl+C`。
5. 在 `start_relocalization.launch` 终端按 `Ctrl+C`。
6. 在 `base_system.launch` 终端按 `Ctrl+C`。
7. 确认没有地图保存过程正在进行，再按设备规程断电。

## 11. 快速排错

| 现象 | 首先执行 | 处理原则 |
|---|---|---|
| 找不到 `ground_air_msgs` 服务类型 | `source ~/catkin_ws/devel/setup.bash` | 每个新终端都要 source |
| 无注册点云 | `rostopic hz /cloud_registered` | 查 Livox、IMU、FAST-LIO |
| 仍显示 `_1`/`_loc` 旧话题 | `rosnode info /fast_lio_node` | 结束旧 launch 并重启，禁止启动第二套 FAST-LIO |
| 不能切 POSITION | `rostopic hz /mavros/odometry/out` | 查外部里程计和 MAVROS 状态 |
| 地图开始后点数为 0 | 等待并看 mapping status | 初始可为 0，持续为 0 才排错 |
| 地图加载失败 | 检查四个地图文件 | 不修复前不重定位 |
| 重定位失败 | 查 frame、点云、场景重叠 | 换结构明显位置，保持静止 |
| `valid` 变 False | 查点云是否超过 2 s 无更新 | 停止导航并重新定位 |
| 无全局路径 | `make_plan` 零容差检查 | 目标换到已知自由区 |
| 高速原地转圈 | 遥控器接管并急停 | 取消目标，确认恢复参数关闭，重启 move_base |
| 障碍附近左右摆动 | 急停并保存 local plan/costmap | 暂不提高速度或关闭障碍层，等待 TEB 调参复测 |
| 多点任务 `state=5`、move_base `status=4` | 急停、取消 Action | 该任务失败；分别检查每个目标的精确路径、朝向和局部可行性 |
| `/prepare_ground` 提示需要手动解锁 | 查 `/mavros/state` 的 `armed` | 使用遥控器解锁，程序不会代为解锁 |
| `/prepare_ground` 提示需要手动 OFFBOARD | 查 `/mavros/state` 的 `mode` | 使用遥控器切入 OFFBOARD，程序不会代为切换 |
| 切回 POSCTL 后车辆无 ROS 驱动 | 这是预期行为 | 地面速度路由器在非 OFFBOARD 状态强制停止 |
| 解除急停失败 | 查 `/ground_air/vehicle_status` 和 FCU 连接 | 不重复盲调，保持停止 |

## 12. 一页式流程

```text
开机和 GroundControlStation 检查
        │
        ├── 建新地图
        │     start_mapping.launch map_id:=<新地图ID>
        │     → 检查点云/里程计
        │     → 自动开始记录，确认 mapping state=1
        │     → 遥控器低速驾驶
        │     → save_mapping.launch
        │     → 检查四文件
        │
        └── 使用历史地图自主导航
              base_system.launch
              → start_relocalization.launch map_id:=<历史地图ID>
              → 自动 load_map
              → 自动 relocalize（不启动运动）
              → valid/fitness/rmse/TF 检查
              → task_system.launch（软件急停默认关闭，20 Hz 控制链）
              → make_plan tolerance=0.0
              → 遥控器手动解锁并切入 OFFBOARD
              → 确认软件急停为 False（异常锁定时查因后再解除）
              → prepare_ground 只读确认
              → mission/submit 提交 map 坐标目标
              → mission/start 启动任务
              → 监控运行
              → 到点急停
              → 遥控器手动切回 POSCTL
              → 取消旧任务并正常停机

指控平台选点入口
        → task_system.launch start_ccs_task_adapter:=true
        → 平台把选点转换为 map 绝对坐标
        → 生成并下发任务 XML（当前点 + 目标点）
        → PREPARE 校验并提交
        → SCHEDULE 启动
        → move_base 规划、实时避障和执行
        → execution_feedback 返回进度与结果
```

底层 `manual_mapping.launch`、`autonomy.launch` 和四个地图/定位服务仍保留用于开发诊断；日常操作优先使用三个正式入口，避免漏调服务或启动运动模块。
